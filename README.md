# 航士朗 ホームページ

GitHub Pages で無料公開している静的サイト。レトロ版は HTML/CSS のみ（JavaScriptなし）、今風版は自サイト内の `main.js` と `player.js` だけを使う。

| ファイル | 内容 |
|---|---|
| `index.html` / `retro.css` | トップ（阿部寛HP風レトロ版） |
| `modern.html` / `style.css` | 今風デザイン版 |
| `main.js` | 今風版の補助スクリプト（トップの「弾ける海」＝触れると波紋が広がり、「音を出す」を押したあとは音も鳴る／絵の奥行き／メニューの現在地表示／古いブラウザ向けの代替表示）。無くても全部読める |
| `player.js` | 今風版の曲リスト用プレーヤー（再生ボタン・波形・曲の切り替え）。動かない環境ではブラウザ標準の再生バーが出る |
| `video.js` | 今風版の歌詞動画の欄（一覧を押すと上の画面で流れる）。動かない環境では一覧が動画ファイルへのリンクになる |
| `videos/` | 歌詞動画（`曲名.mp4`）と、一覧に出す絵（同じ名前の `.jpg`） |

| `fonts/` | 今風版の見出し用フォント（Syne / しっぽり明朝、いずれもOFLライセンス。ライセンス文を同梱） |
| `images/hero-bg.jpg` / `images/hero-figure.webp` | 今風版のトップの絵。奥の景色と、手前の人物（背景透明）の2層。差し替えるときは同じファイル名で上書きする |
| `images/` | 写真・背景画像 |
| `.nojekyll` | GitHub Pages の Jekyll 変換を無効化 |

## セキュリティ方針（今風版でJavaScriptを使う条件）

- CSP（`modern.html` の `<meta>` と `vercel.json`）で **自サイト内のファイルだけ** を許可：`script-src 'self'` / `style-src 'self'` / `font-src 'self'` / `img-src 'self'` / `media-src 'self'`（音源）
  → 外部スクリプト・インラインスクリプト・`eval` はブラウザが実行を拒否する（XSS・改ざんされた外部CDN経由の攻撃を防ぐ）
- `main.js`・`player.js` は通信しない・Cookie等に保存しない・入力を受け取らない・`innerHTML` を使わない
- 音は音声ファイルを読み込まず `main.js` がその場で計算して鳴らす（マイク・外部通信は使わない）。「音を出す」ボタンを押すまで鳴らない
- フォーム・ログイン・データベースを持たない（攻撃される対象を作らない）
- レトロ版（`index.html`）は引き続き JavaScript 完全禁止
- スクリプトやフォントを追加するときは **必ずリポジトリ内に置く**（CDNのURLを書かない）
- GitHubアカウントは二段階認証を有効にする（サイト改ざんの最大の入口はアカウント乗っ取り）

## 見た目や動きのファイルを直したとき

`modern.html` の中で `style.css?v=…`・`main.js?v=…`・`player.js?v=…`・`video.js?v=…` と書いてある `v=` の値を、すべて新しい値（例：日付）に変える。
GitHub Pages はファイルを10分ほどブラウザに覚えさせるため、変えないと「新しいページ＋古いスタイルやスクリプト」が混ざって、表示崩れやボタンが効かない状態になることがある。

## 曲を追加するとき

1. 音源を `audio/` に置く（iPhoneでも確実に鳴る AAC の `.m4a` か `.mp3` にする）
2. ジャケット（正方形・600×600px 以上の JPEG）を `images/` に置く
3. `modern.html` の `<ol class="tracklist">` の `<li>` を丸ごとコピーし、`data-src`・`data-seconds`・`data-art`・曲名・長さを書き換える
4. 波形（`data-peaks`）は、音源の音量を180個の数字（0〜100、カンマ区切り）にしたもの。作り方が分からなければ `50` を180個並べても動く（平らな波形になる）
5. 歌詞は `<div class="lyrics-full" data-track="1">`（番号は0始まり）を足す
6. レトロ版（`index.html`）の「★★★　曲　★★★」の表にも、最後の `<tr>` を丸ごとコピーして番号・曲名・長さ・`src` を書き換えた行を足す。「最新情報」にもお知らせを足す（新しいものを上に）

## 独自ドメインへの移行手順

### 移行しやすくするための約束事（今から守る）

- リンク・画像は **相対パス** で書く（`images/photo-2.png` ○ ／ `/images/photo-2.png` ✕ ／ `https://anzuka10n12.github.io/...` ✕）
  → `/koshiro/` 配下でもドメイン直下でもそのまま動く
- サイト内に `github.io` のURLを直書きしない（例外：`index.html`・`modern.html` の `og:url` / `og:image` はSNS共有の仕様上フルURL必須 → 移行時に書き換える）
- SNSのプロフィール欄には、移行後は独自ドメインのURLを載せ直す

### 1. ドメイン取得

- 取得先の例：Cloudflare Registrar（原価販売・更新料が上がらない）、お名前.com、ムームードメイン など
- 費用の目安：`.com` 年1,500〜2,000円程度、`.jp` 年3,000〜4,000円程度（業者・時期で変動）
- WHOIS情報公開代行（個人情報を隠す設定）を必ずONにする

### 2. GitHub側でドメインを「検証」する（乗っ取り防止）

1. GitHub 右上アイコン → Settings → Pages → 「Add a domain」
2. 表示された TXT レコード（`_github-pages-challenge-anzuka10n12`）をDNSに登録 → Verify
   - 検証しておくと、第三者に自分のドメインを悪用される「サブドメイン乗っ取り」を防げる

### 3. DNSレコードを設定（ドメイン業者の管理画面）

ドメイン直下（例：`okakoshiro.com`）で公開する場合：

| 種類 | ホスト | 値 |
|---|---|---|
| A | @ | 185.199.108.153 |
| A | @ | 185.199.109.153 |
| A | @ | 185.199.110.153 |
| A | @ | 185.199.111.153 |
| AAAA | @ | 2606:50c0:8000::153 |
| AAAA | @ | 2606:50c0:8001::153 |
| AAAA | @ | 2606:50c0:8002::153 |
| AAAA | @ | 2606:50c0:8003::153 |
| CNAME | www | anzuka10n12.github.io |

※ 値は移行時に GitHub Docs「Managing a custom domain for your GitHub Pages site」で最新を確認すること

### 4. リポジトリ側の設定

1. `koshiro` リポジトリ → Settings → Pages → Custom domain にドメインを入力して Save
   （リポジトリ直下に `CNAME` ファイルが自動作成される）
2. DNS反映後（数分〜最大48時間）、**Enforce HTTPS** にチェック

### 5. 移行後の確認

- [ ] `https://独自ドメイン/` と `https://www.独自ドメイン/` の両方で表示される
- [ ] 鍵マーク（HTTPS）が付いている
- [ ] 旧URL `https://anzuka10n12.github.io/koshiro/` が新ドメインへ自動転送される（GitHub が自動で行う）
- [ ] SNSプロフィールのURLを書き換えた
- [ ] `og:url` / `og:image` を新ドメインに書き換えた

### 注意

- ドメインの更新を忘れて失効すると、他人に取得されて悪用される恐れがある → **自動更新をON**にする
- ドメインをやめる時は、先に GitHub の Custom domain を外してから DNS を消す
